# Сервер планировщика: раздача и «не засыпать в рабочее время»

Приложение раздаётся BFF-сервером (`bff.py`) через systemd-юнит `planner.service`
(порт 3000). Файлы приложения лежат в `/opt/app` на VM (хостинг vibecode,
режим BLACKHOLE — доступ только через шлюз).

## Часовой пояс VM

VM переведена в `Europe/Moscow` (UTC+3, совпадает с Минском):

```
timedatectl set-timezone Europe/Moscow
```

## «Не засыпать» в рабочее время (Пн–Пт 09:00–18:00 МСК)

Сервер по умолчанию засыпает после 60 минут простоя (`sleepAfterMinutes: 60`).
Чтобы он бодрствовал в рабочее время, используются два механизма:

1. **Wake-schedule платформы** (будит спящий сервер по расписанию — например,
   первый заход утром после ночного сна):

   ```
   POST /v1/infra/servers/:id/wake-schedules
   { "cronExpr": "0,30 9-18 * * 1-5", "timezone": "Europe/Moscow" }
   ```

2. **In-VM keep-alive** (`/opt/app/keepawake.sh` + `/etc/cron.d/planner-keepawake`):
   каждые 20 минут в 09:00–18:00 МСК (Пн–Пт) делает аутентифицированный запрос
   к приложению через шлюз — это доходит до VM и считается активностью, поэтому
   60-минутный таймер простоя не срабатывает.

   ```
   */20 9-18 * * 1-5 root /opt/app/keepawake.sh
   ```

   Скрипт минтит короткоживущий `api-bearer` токен по ключу приложения
   (`X-Api-Key`, хранится только на сервере) и обращается к `/api/whoami`.
   Вне окна активность не генерируется — сервер засыпает как обычно (экономия).

> Примечание: `keepawake.sh` и cron-файл лежат на диске VM и переживают сон, но
> могут быть стёрты при полном пересоздании сервера — тогда их нужно поставить
> заново. Ключ приложения в скрипт подставляется при установке и в репозиторий
> не коммитится.
